- (decision by user) Public Shared List is a narrow unauthenticated database read: SELECT only the rows the public profile may show (that User's going/attended Concerts, no notes, no Bill-only, no disabled profile). Event, notes, Bill-only, and private Events require a signed-in owner or joiner. Event URL is not world-readable; unsigned visitor must sign in then join. Prevents a too-wide public read (notes/private bill) and prevents forcing login on the public profile via a privileged server path.
- (decision by user) Going becomes attended at read time (user wrote 'au moment où on mit' = lit). Europe/Paris: after optional time, else end of that local day. Reads (UI, MCP, public profile) expose attended when the Concert is past; writes refuse to store going on a past Concert (store attended). No background job in v1. Prevents UI showing attended while public profile still shows Going, and prevents a cron as a second mutation path.
- (decision by user) MCP authenticates with a user-issued personal key (create/revoke in the app), not email/password in the agent config, not OAuth in v1. A small server route exchanges the key for a user-scoped session so the shared domain module runs as that User (same rights as UI). Store the key hashed, never plaintext; v1 revoke-only (no expiry policy). This is an allowed Nitro exception to path A. Prevents a privileged MCP bypass and prevents password-in-agent-config.
- (decision by user) v1 Event URL is the Event's opaque random id (UUID); that page URL is the unguessable Event link. Pretty/vanity slugs (e.g. /e/rock-en-seine-2026) are deferred to v2 for selected big Events only. Prevents sequential public ids and prevents making a readable name the Event's identity in v1.
- (decision) Keep v2 cheap: Event identity remains the opaque id forever. A future pretty slug is an optional alias that points at that id (redirect or extra lookup), never a replacement id. Renaming the Event does not change the v1 link.
- (decision by user) v1 has one human identifier: username. Chosen at registration, unique case-insensitive (a-z0-9_- per SPEC), immutable in v1, used as the public profile URL and as the name shown in the UI. No separate display_name. Existing profiles.display_name is replaced/repurposed by username. Prevents cards using display_name while the profile URL uses a different username, and prevents a rename/migration story in v1.
- (decision by user) Civil time, not UTC-as-source-of-truth: Event start_date/end_date are calendar dates; Concert has a calendar date plus optional clock time; all interpreted in Europe/Paris. Past = after that time in Paris, or after end of that Paris day if no time. Writes store those civil values. Prevents two implementations inventing different UTC instants for dateless concerts. Entity ids (Event, Concert, Attendance, membership, personal keys) are UUIDs like auth users — no public sequential numbers.
- (decision by user) Membership is its own table (event_id + user_id). Join inserts a row; leave deletes that row and that User's Attendance on that Event's Concerts. Event.owner_id is separate — the owner is not a membership row. Attendance is not membership: a member may have zero Attendance. Prevents 'has any going/attended' as join, and prevents leave leaving orphan Attendance.
- (decision by user) Stages/Scenes are real rows on the Event (UUID id + name). Concert references stage_id, not a copied name. Empty list = stage not required on Concerts. Rename keeps Concerts attached. Prevents copied stage strings going stale on rename.
